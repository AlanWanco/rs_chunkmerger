# rs_chunkmerger

一个用 Rust 编写的高效媒体分片合并工具，支持自动排序、DASH/HLS 分片处理及可选的 FFmpeg 转码。

## 功能特性

- **多格式支持**：支持 `.ts`, `.decrypt`, `.mp4`, `.m4s` 等常见媒体分片格式。
- **智能排序**：按文件名中的数字编号排序，不受 `678`、`0679` 等位数/前导零变化影响；支持 `00_002090_index_4_2185.ts` 这类多编号命名。至少三个不同尾号且变化字段与尾号差值恒定时才归为同一序列，固定轨道标识仍保留。
- **分片检查**：合并前检查全部候选文件、编号范围和数量；报告编号缺片及重复编号，并按二进制内容去除完全重复的分片。
- **TS 文件识别**：检查 `.ts` 的 MPEG-TS 包同步数据，跳过 TypeScript 源码；TS 分片大小异常时进一步核对二进制包同步。
- **音视频分轨复用**：同一目录内唯一的一组编号音轨和视频轨会由 `ffprobe` 识别并检查时间范围；用户确认后由 FFmpeg 单次读取、检查全部包的 PTS/DTS 并无损复用。时间线异常或无法探测时不会发布输出文件。
- **缺片处理**：发现编号缺口时，可选择在缺片处拆分成多个视频。
- **DASH 支持**：自动识别并优先放置包含 `init` 字样的初始化文件。
- **自动转码**：合并完成后可自动调用 FFmpeg 将 TS 转换为 MP4（需系统已安装 FFmpeg）。
- **跨平台支持**：支持 Windows、Linux 和 macOS（Apple Silicon/Intel）。
- **隐藏文件过滤**：默认跳过隐藏文件、dotfile 和 macOS 隐藏目录；需要时可使用 `--include-hidden` 包含。
- **扫描范围安全**：默认只扫描输入目录当前层；`--recursive` 可扫描子目录，但每个目录会独立预览、确认和合并，不会跨目录拼接。递归结果输出到扫描根目录的上一级，并带子目录名，避免输出再次被扫描。
- **指定输入目录**：`--this-dir` 从启动命令时的当前工作目录扫描，与程序安装位置无关；也可使用 `--input-dir <目录>` 指定其他目录。
- **简单易用**：直接在包含分片的文件夹中运行即可，输出文件会自动存放在上级目录。

## 安装说明

### 从 Release 下载
前往 [Releases](https://github.com/your-username/rs_chunkmerger/releases) 页面下载适用于您系统的预编译二进制文件。

### 自行编译
确保已安装 [Rust](https://www.rust-lang.org/) 环境，然后运行：

```bash
cargo build --release
```

编译产物位于 `target/release/rs_chunkmerger`（Windows 下为 `.exe`）。

## 使用方法

查看完整帮助或版本号（直接退出，不扫描目录、不执行合并）：

```bash
rcm --help     # 也可使用 -h
rcm --version  # 也可使用 -V
```

1. 将编译好的程序（或下载的二进制文件）放到存放视频分片的文件夹中。
2. 直接运行程序。
3. （可选）如果不想转换为 MP4，可以带参数运行：
   ```bash
   rs_chunkmerger --ts
   ```
4. 默认不会合并隐藏文件和 dotfile；如需包含这些文件，可以运行：
   ```bash
   rs_chunkmerger --include-hidden
   ```
5. 如果程序已加入 PATH，可从待合并目录调用 `--this-dir`；或明确指定其他输入目录：
   ```bash
   cd /path/to/chunks
   rcm --this-dir
   # 也可从其他目录指定路径
   rcm --input-dir /path/to/chunks
   # 需要扫描子目录时显式启用；各目录会分别处理
   rcm --this-dir --recursive
   ```
6. 程序会先展示扫描范围、文件数及检查警告；命名规律不足时会提示可能选错目录。确认后才开始合并。检测到编号缺片时，还会询问是否按缺口拆分输出。
7. 独立音轨和视频轨需要 `ffmpeg` 与 `ffprobe`。默认复用为 MP4；使用 `--ts` 时复用为 MPEG-TS。自动配对目前限同一目录内唯一的音轨/视频轨；缺少初始化片段、无法探测或非 TS 轨超过 128 片时会停止自动配对。

### 手动选择合并范围

`--start` / `--end` 选择排序、去重后的有效文件列表中的连续范围，包含首尾文件；只指定一个边界时，另一端默认为列表首尾。

```bash
# 完整文件名（含扩展名；有空格时加引号）
rcm --start "00_002090_index_4_2185.ts" --end "00_002110_index_4_2205.ts"
# 纯数字可以匹配任意完整数字字段，忽略前导零
rcm --start 002090 --end 2110
# 只有数字不匹配任何文件名字段时，才按从 1 开始的文件顺序号解析
rcm --start 10 --end 20
```

匹配优先级：

1. **完整文件名**：优先匹配文件名，不做前缀或子串匹配。
2. **文件名数字**：纯数字输入匹配文件主名中的完整数字字段；`2090` 可匹配 `002090`，但 `20` 不会匹配 `2090`，扩展名 `.mp4` 的 `4` 不算编号。同一文件内多个字段命中只算一个文件；多个文件命中则报错，需改用完整文件名，不会悄悄退回顺序号。
3. **文件顺序号**：没有数字字段命中时才回退，合法范围是 `1` 到有效文件数。起点和终点可分别使用不同匹配方式。

程序会在确认前逐项展示匹配方式、实际文件名、原列表位置及选中范围；边界不存在、顺序号越界、起点晚于终点时以非零状态退出，不生成输出。只对选中范围重新检查缺片。范围若排除了已发现的初始化片段也会报错，不会自动追加范围外文件。

使用 `--recursive` 时，各目录独立解析同一组边界；任一目录范围无效会在执行合并前停止全部任务。

## 注意事项

- **FFmpeg**：若需自动转换为 MP4，请确保 `ffmpeg` 已添加到系统 PATH 中，或将本地 `ffmpeg`/`ffmpeg.exe` 放在程序同级目录下。
- **文件命名**：输出文件名将结合当前文件夹名、版本号以及分片的起始/结束编号。
